# Правила разработки 1С — вариант для чата

В чате у Claude нет доступа к файловой системе проекта. Файлы контекста пользователь загружает в чат, а новые файлы Claude отдаёт как результат (для скачивания или в виде текстового блока).

## 1. Файлы контекста проекта

| Файл | Назначение | Как использовать в чате |
|---|---|---|
| `Versions.md` | Версионный стек проекта | Загрузить в чат. Если нет — Claude подготовит его содержимое для сохранения в проект |
| `Project.md` | Контекст задачи и проекта | Загрузить в чат. Отсутствие допустимо |
| `Readme.md` | Список добавленных skills: название, для каких задач применять, путь, примечание | Загрузить в чат, если нужны skills |
| `v8std_bsl_rules.md` | Резервные правила, если коннектор v8std недоступен | Загрузить в чат при необходимости |

### 1.1. Версионный стек

Зафиксируй и строго соблюдай: версию платформы 1С, **режим совместимости**, версию конфигурации, версии библиотек (БСП и др.).

- Если `versii.md` загружен — опирайся на него.
- Если не загружен — запроси у меня данные: платформа, режим совместимости, версия конфигурации, версия БСП и других библиотек. Ничего не угадывай. После получения данных подготовь содержимое `versii.md` и предложи его как файл, чтобы я сохранил его в папку проекта.
- Справку бери по версии платформы, но **не предлагай API, недоступный в режиме совместимости проекта**. Справку БСП бери по реальной версии БСП проекта.
- Если не уверен, что метод, объект или реквизит существует в этой версии, скажи об этом. Не выдумывай API.

### 1.2. `project.md`

Если файла нет в чате, предложи мне его загрузить. Отсутствие файла допустимо, тогда продолжай без него.

### 1.3. `Readme.md` (skills)

Если загружен `Readme.md`, выбирай подходящий skill из списка. Если подходящего skill нет, скажи об этом и не придумывай его. Для работы с расширениями применяй skills `cfe-*`, если они указаны в `Readme.md`.

## 2. Перед началом работы

- Не пиши код сразу. Сначала проанализируй задачу и текущий код (код и структуру метаданных я присылаю в чат).
- Если есть несколько вариантов решения, предложи их с краткими преимуществами и недостатками.
- Явно перечисли неопределённости в исходных данных и контексте. Не предполагай и не додумывай. Если нет структуры метаданных или других исходных данных — запроси их.
- **Исключение для мелких правок** (несколько строк, без изменения логики): можно сразу писать код, указав допущения. Для остального обязательны анализ, неопределённости и варианты.
- **Основная конфигурация или расширение.** Если у проекта есть расширения, обязательно уточни, где вносить изменения. По умолчанию не предлагай правку в основной конфигурации.
- После анализа кода сообщи об ошибках и проблемных местах, не связанных с задачей, отдельным списком. **Не исправляй их без моего разрешения.**

## 3. Выполнение задачи

- Применяй правила и стандарты разработки через коннектор **v8std** (`https://ai.v8std.ru/mcp`). Если он недоступен — используй `v8std_bsl_rules.md`, если я его загрузил. Если недоступно и то и другое — скажи об этом.
- После написания кода проверь его по v8std. В ответе укажи, какие стандарты проверены и какие замечания остались.
- Учитывай замечания BSL LS, если я их присылаю.

### Приоритеты

1. Мои явные указания в задаче.
2. Ограничения из раздела 5.
3. Стандарты v8std — для нового кода.
4. Стиль существующего кода — его без запроса не переписывать. Если он расходится со стандартами, сообщи об этом.

## 4. Стандарты кода

- **Язык и стиль:** комментарии на русском, именование по стилю БСП.
- **БСП:** если в версии БСП проекта есть нужная функция, используй её, а не пиши свою (`ОбщегоНазначения`, `РаботаСФайлами`, `УправлениеДоступом` и др.).
- **Клиент и сервер:** минимум серверных вызовов, `&НаСервереБезКонтекста`, не передавай тяжёлые объекты на клиент.
- **Запросы:** параметры вместо конкатенации строк; `РАЗРЕШЕННЫЕ`, где нужен учёт прав; отборы в параметрах виртуальных таблиц; временные таблицы для сложных выборок; без соединений с подзапросами.
- **Транзакции и блокировки:** короткие транзакции, управляемые блокировки; ошибки пиши в журнал регистрации (`ЗаписьЖурналаРегистрации`).
- **Безопасность:** не использовать `Выполнить` и `Вычислить` с внешними данными; привилегированный режим — только при необходимости и на минимальном участке.
- **Локализация:** `НСтр` для пользовательских строк, если конфигурация многоязычная.
- **Обновление данных:** если меняется структура данных, нужен обработчик обновления.

## 5. Ограничения

- Не меняй типовые модули и структуру объектов без согласования.
- Не создавай новые объекты конфигурации без согласования.
- Не делай запросы в цикле: собирай отбор по массиву, один запрос — одна выборка. Это касается и обращений к реквизитам через точку, и `ПолучитьОбъект()` в цикле. Исключения согласуй со мной.
- Не меняй имена существующих методов и переменных в существующем коде. В новом коде называй по стандартам. Переименование существующего — только по согласованию.
- Не исправляй проблемы вне задачи без разрешения.

## 6. Формат ответа

1. Неопределённости и вопросы.
2. Варианты решения (если они есть).
3. Код — отдельными блоками с указанием объекта, модуля и процедуры. Показывай только изменённые процедуры целиком, не переписывай модуль.
4. Чек-лист: что проверено (v8std, режим совместимости, контекст клиент/сервер, права), что не проверено и почему.
5. Проблемы вне задачи (если нашёл).
